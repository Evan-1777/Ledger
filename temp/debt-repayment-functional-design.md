# 负债还款与主系统业务衔接功能设计方案（修订版 v1.1）

> 本文为负债渠道还款业务的功能设计与架构推演文档。旨在理清财务逻辑、梳理系统数据流，并解答从记账操作到宏观资产统计中的关键衔接问题。

---

## 1. 业务背景与财务本质认知

在记账系统中，“还款”是连接**资产账户**与**负债账户**的核心枢纽。对于个人记账爱好者而言，还款操作往往容易与常规的“支出”混淆。为了建立清晰的认知，首先明确还款在财务学上的本质定位：

> [!NOTE] **财务常识：还款为什么不是「支出」？**  
> 当您使用信用卡消费 100 元购买晚餐时，您的净资产已经减少了 100 元，此时已产生了一笔真正的**「生活支出」**（餐饮）。  
> 月末您从储蓄卡转账 100 元偿还信用卡时，储蓄卡（资产）减少了 100 元，信用卡欠款（负债）也减少了 100 元。这一过程只是资金在不同账户之间的**「内部转移与债务结算」**，您的总财富（净资产）没有发生任何变化，因此绝对不能再次记为「支出」，否则会导致当月生活花费被重复统计。

## 2. 核心衔接盲点深度排查（6 大关键问题与解法）

围绕核心诉求：*“新增还款与支出和收入并列，还款时将类型锁住，渠道从负债渠道里选”*，推演排查出以下 6 个必须在架构层妥善解决的关键问题：

### 问题 1：资金从哪里扣？（单边还款 vs 双边联动还款）
- **现象**：如果仅选择负债渠道（如招行信用卡），信用卡欠款虽被冲减，但用户的资产账户（如招行储蓄卡、微信零钱）未发生扣减，导致总资产不变、负债减少、净资产凭空暴增。
- **解法**：支持**双渠道资金链路**。还款时以【还入负债渠道】为必选，同时提供【转出资产渠道】选项（支持指定具体资产账户，或选择“外部/未在账本记录资金”）。选定资产渠道时，系统联动扣减资产余额，保持会计恒等式 `净资产 = 资产 - 负债` 严格守恒。

### 问题 2：报表与统计指标的污染隔离
- **现象**：系统当前以 `amount_cents < 0` 算花费、`amount_cents > 0` 算收入。还款存入正金额会被收入与月度趋势误算为收入，导致损益失真。
- **解法**：数据库显式增加 `type` 列（`expense`/`income`/`repayment`）。统计接口的花费、收入、趋势双柱图、分类下钻全面增加 `type != 'repayment'` 过滤，物理杜绝损益报表失真；流水列表筛选中，`type=income` 与 `type=expense` 也同步按 `type` 严格隔离。

### 问题 3：“锁住类型不让选”与系统分类保护（ID 级根因防护）
- **现象**：`transactions` 表有 `category_id NOT NULL` 外键约束。若分类可被重命名或删除，按名称回填会失效。
- **解法**：
  1. 系统在热迁移阶段（早于种子检查）自动预置单系统分类「债务偿还」及单标签「负债还款」；
  2. 将系统分类与标签的 ID 持久化写入 `system_meta` 表；
  3. 服务端删除守卫与重命名守卫均直接比对该 ID，彻底杜绝被改名或误删击穿；
  4. 还款时前端自动绑定该 ID 并置为锁态，无需用户挑选。

### 问题 4：负债渠道额度使用率与可用额度的实时动态响应
- **现象**：还款成功后，欠款下降，剩余可用信用额度（`credit_limit - current_debt`）需即时回升，额度使用率导轨自洽回落。
- **解法**：还款金额正向计入负债流水求和，欠款自动减少，联动驱动前端 4px 紧凑进度导轨与状态呈现。

### 问题 5：新增与编辑路径的完整性与类型锁定
- **现象**：更新路径（PUT）若未同步更新 `type` 与 `source_payment_method_id`，编辑模式下数据无法保存；若允许编辑时随意切换收支与还款类型，会引发分类与渠道撕裂。
- **解法**：
  1. `TransactionRequest` 补齐 `type` 与 `source_payment_method_id`，PUT 接口支持全字段更新；
  2. 编辑模式下，前端 3 段滑块锁定为只读禁用态（禁止跨类型篡改），但允许在还款类型下修改金额、备注、还入渠道、转出渠道与时间；
  3. 服务端强制校验还款金额必须大于 0（`amount > 0`），杜绝负数还款反向增加欠款。

### 问题 6：日分组小计与溢缴款自洽
- **现象**：流水页按天分组的小计若仅按金额正负求和，会将正数的还款金额计入“收入 ¥xxx”中。
- **解法**：
  1. 流水日分组小计仅对 `type === 'expense'` 与 `type === 'income'` 进行聚合，排除还款污染；
  2. 溢缴款（欠款为负）时，可用额度上限自洽约束在授信额度本身，净资产数学公式恒定成立。

## 3. 三大业务模式交互与行为对比矩阵

| 维度 | − 支出 (Expense) | + 收入 (Income) | ↺ 还款 (Repayment) |
|---|---|---|---|
| **业务含义** | 日常生活消费，导致净资产减少 | 薪资、投资等收益，导致净资产增加 | 偿还债务，净资产恒定守恒 |
| **分类与标签** | 必选（二级级联 Flyout 自主挑选） | 必选（二级级联 Flyout 自主挑选） | 🔒 强制锁定（固定为系统预置「债务偿还 · 负债还款」） |
| **渠道候选池** | 全渠道（资产或负债） | 资产渠道 | 必选还入负债渠道 + 可选转出资产渠道 |
| **损益统计影响** | 计入本周/当月/上月花费 | 计入当月收入与月度结余 | 严格隔离，不计入日常消费和经营收入 |
| **流水筛选与小计** | 归入“支出”筛选与支出日小计 | 归入“收入”筛选与收入日小计 | 独立“还款”筛选档位，不计入收入小计 |
| **资产负债影响** | 资产减少 或 负债增加 | 资产增加 | 负债欠款减少，转出资产渠道同步扣除 |
| **编辑修改规则** | 类型锁定，可改金额/备注/分类/渠道 | 类型锁定，可改金额/备注/分类/渠道 | 类型锁定，可改金额/备注/还入渠道/转出渠道 |

## 4. 前端交互与视觉规范演进

遵循项目的 Microsoft Fluent 2 视觉语言规范：

### 4.1 记账模态窗（RecordModal）
1. **顶部 3 联胶囊滑块**：
   - 布局升级为 `grid-cols-3`（`− 支出` | `+ 收入` | `↺ 还款`）；
   - 滑块使用 GPU 加速位移（`translateX(0%)` / `translateX(100%)` / `translateX(200%)`）；
   - 选中「还款」时呈现品牌强调色与专属标识（`↺ 还款`）；
   - **编辑已有账单时**，滑块置为不可交互锁定态，防止破坏账务类型契约。
2. **分类与标签展示区**：
   - 还款模式下置为静置只读卡片，禁用 Hover 与点击，显示：`债务偿还 · 负债还款` 并附带精细小锁图标。
3. **渠道选择区域**：
   - 「还入负债账户」：仅渲染 `type === 'liability'` 渠道，必选；
   - 「转出资产账户」：提供单选列出 `type === 'asset'` 渠道及“外部/不记账资金”选项，默认选中首个资产渠道。

### 4.2 账目流水页（StreamPage）与筛选胶囊（BottomBar）
1. **底部筛选胶囊**：升级为 `全部 | 支出 | 收入 | 还款` 4 档位；
2. **流水卡片呈现**：
   - 还款金额使用 Fluent 品牌蓝（`#0078D4`）呈现（`¥500.00`），无红绿正负号歧义；
   - 渠道位置显示资金流转路径：若有转出资产渠道，显示 `招行储蓄卡 → 招行信用卡`，否则显示 `还入 招行信用卡`；
   - 日分组小计严格排除还款记录，保持当日纯消费与纯收入统计精准。

## 5. 数据存储与 API 契约演进方案

### 5.1 数据库结构升级（探针热迁移）
在 SQLite `transactions` 表中通过探针安全增加两列：
```sql
-- 交易类型：'expense' | 'income' | 'repayment'
ALTER TABLE transactions ADD COLUMN type TEXT NOT NULL DEFAULT 'expense';

-- 联动转出资产渠道 ID（仅还款时可关联）
ALTER TABLE transactions ADD COLUMN source_payment_method_id INTEGER DEFAULT NULL REFERENCES payment_methods(id) ON DELETE RESTRICT;
```

### 5.2 接口契约对照
- `GET /api/transactions?type=expense|income|repayment`：按 `type` 字段精准过滤流水；
- `POST /api/transactions` 与 `PUT /api/transactions/:id`：
  ```json
  {
    "type": "repayment",
    "amount": 1000.00,
    "description": "归还本月招行信用卡",
    "payment_method_id": 3,
    "source_payment_method_id": 1,
    "transacted_at": "2026-10-03T12:00:00Z"
  }
  ```
- 服务端校验：
  - `repayment` 类型下 `amount > 0` 且 `payment_method_id` 必须为 liability 渠道；
  - `source_payment_method_id` 若存在必须为 asset 渠道；
  - 自动绑定系统内置「债务偿还」分类与标签 ID。

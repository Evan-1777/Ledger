## 1. 背景与目标

用户提供 4 张 Android 客户端截图，分别指出资产页金额列未对齐、统计页指标卡行底不齐、统计图表卡内部可滚动且切换后留白、流水页筛选行占用整行面积。随后新增要求：实际应用顶栏过低，四个一级页统一改为 Demo 手机框内的紧凑顶栏，且顶栏要随内容滑动被推上去。

本轮目标：

- 在 Flutter 客户端根因处修正 5 组布局问题，保持现有 Material 3 视觉体系与交互语义。
- 四个一级页统一使用 64 高、非 pinned 的紧凑顶栏，标题上移到顶栏中心，并随内容滚动被推上去；设置页只改顶栏，不改内容。
- 资产与负债金额列共享同一条右侧边界，隐藏金额、负余额着色和窄屏缩放不回归。
- 统计页四张指标卡统一等高；图表卡由内容决定高度，构成图不再内部滚动，趋势图不再继承构成图高度。
- 流水页筛选不再独占一行；当前筛选可见，五种筛选仍可直接选择。
- 不新增依赖、不修改后端接口、不修改 Web React 界面；320dp + 2x 字体无溢出。
- 为每组修复添加可机械验证的 Widget 回归断言，替代人工目测。

**设计哲学**：沿用项目既有 Material 3（加载 `frontend-design`、`production-frontend` 与 `material-3`），不引入 Fluent 或 Apple 体系。规划段产出静态预览 `temp/uiux-fixes-demo.html`：默认展示修复后，支持修复前/后、构成/趋势、筛选菜单与明暗主题切换；预览只呈现受影响区域与必要上下文，不重抄整页。

**本轮范围**：Flutter 客户端（`app/`）的资产页、统计页、流水页、四个一级页共用的顶栏，以及对应 Widget 测试；设置页仅纳入顶栏改造。

**范围外**：Web React 端、Go API/SQLite、Android 构建配置、版本号与 CI 发布流程。截图为 Flutter 客户端，本轮不扩散到 Web 端同类组件。

## 2. 现象与根因结论

| 编号 | 截图现象 | 根因 | 修正方向 |
|------|----------|------|----------|
| A | 资产与负债金额列停在卡片中部，`余额/欠款`与右侧留白不一致 | 金额列是弹性行中的松散子项，按内容宽度停在弹性槽位起点，未填满槽位，也未真正贴右 | 在既有弹性槽位内填满并右对齐，不引入固定宽度 |
| B | 统计四张指标卡行底不齐；第二行左卡明显矮于右卡，整块 2×2 网格不对称 | 指标网格使用 `Wrap`，每张卡按自身备注行独立取高，备注缺失的卡更矮 | 移除 `Wrap`，两行等高；所有卡保留同字号备注行，四张卡统一高度 |
| C | 构成图图例可在卡片内部上下滑动，最后一项被裁切；切换到趋势后仍保留构成图高度，卡片下方出现大块空白 | 图表卡固定 400 高度，两个图表面板各自内嵌纵向滚动；趋势内容较短但被固定高度撑住 | 图表卡由内容决定高度，移除两个面板的内部滚动，页面统一滚动 |
| D | 流水筛选五枚大胶囊独占一行，可横向滑动；月份说明另占一行 | 筛选胶囊固定 48 高度，外层独立成行；月份与筛选分属两行 | 月份与筛选合并为列表头，筛选收进紧凑菜单，保留 48dp 触达 |
| E | 实际应用顶栏过低，大标题区占首屏，标题离状态栏远 | 四个一级页均使用 `SliverAppBar.large`，展开大标题区把标题压到下方 | 改为共享 `LedgerSliverAppBar`：64 高、非 pinned、20 标题缩进、标题 28/34 居中，随内容滚动上移 |

布局探针的量化结果：

- 资产金额列左缘固定在弹性槽位起点，`45,200.00` 与 `8,200.00` 的右缘相差约 14px，槽位末端仍有约 7–21px 空白。
- 统计指标卡高度为 78.0 / 90.5 / 70.5 / 96.4；四张最大相差 25.9px，第二行左右差 25.9px。
- 构成与趋势图表卡高度均为 488.2，两个模式各有一个内嵌滚动容器；趋势内容不足 400 高度，剩余空间成为卡片内空白。
- 流水筛选行是 48 高度的整行胶囊加 16 间距，和上方的月份行、下方的列表各占一段垂直空间。

## 4. 关键决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 金额列对齐 | 在既有弹性槽位内填满并右对齐 | 一行根因修正覆盖资产与负债两处；不引入固定宽度，长金额与隐藏状态仍受槽位约束 | 给金额列设置固定宽度（在字体缩放和长金额下易裁切）；逐行加空格（脆弱） |
| 指标卡等高 | 四张卡统一高度：两行等高，无备注卡保留同字号备注行 | 截图标注的是整块 2×2 网格；四卡同高后行底和行间都对称；备注行随文本缩放，2x 下不裁切 | 仅行内等高（第二行仍比第一行高，未消除截图指出的整体不对称）；固定卡片高度（2x 字体裁切）；`GridView` 固定比例（内容不可控） |
| 图表卡高度 | 内容驱动，移除内部滚动 | 消除嵌套滚动与裁切；趋势模式自然收缩；所有分类数据直接可见 | 保留固定高度（原缺陷）；限制为 Top N + “更多”（隐藏数据、增加状态）；给趋势图另设固定高度（又回到硬编码） |
| 流水筛选 | 月份与筛选合并为列表头，筛选使用紧凑菜单 | 去掉整行胶囊和独立月份行；筛选贴近其作用的列表，当前选择仍可见；菜单项保留 48dp 触达 | 顶栏筛选按钮（离列表远，且大标题栏会滚动离开）；五段分段控件（320dp + 2x 放不下）；仅缩小胶囊（仍独占一行） |
| 一级页顶栏 | 共享 `LedgerSliverAppBar`：64 高、非 pinned、20 标题缩进、标题 28/34 居中 | 四个一级页一致；消除大标题区的垂直占用；顶栏随内容滑动被推上去；标题与 Demo 手机框顶栏对齐 | 保留 `SliverAppBar.large`（原缺陷）；pinned 固定（用户明确要求随滑动滚出）；每页各写一份紧凑 `SliverAppBar`（重复样式，易漂移） |
| 回归方式 | 布局矩形断言 + 业务请求断言 | 与字体无关、无需图片基线；能直接锁住右缘、行高和内部滚动数量 | Golden 截图基线（维护成本高、跨平台字体差异大） |
| 修改边界 | 仅 Flutter 客户端 | 截图为 Flutter 客户端；Web 与后端没有对应行为变化 | 同步修改 Web（范围扩大，缺少需求依据） |

## 5. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 图表卡改为内容驱动后页面变长，空态/支付途径的滚动断言失效 | 中 | 同步调整测试的滚动距离或使用 `ensureVisible`；禁止通过恢复固定高度解决测试问题 |
| 模式切换导致卡片高度变化，页面滚动位置出现轻微调整 | 低 | 属于内容变化的自然结果；验收只要求无裁切、无空白、无内部滚动 |
| `IntrinsicHeight` 在 2x 字体下增加布局成本 | 低 | 每行仅两张卡，共两行；用 320dp + 2x 测试确认无异常 |
| 无备注卡保留备注行，产生一行留白 | 低 | 为四卡整体对称接受；备注文案与颜色语义不变，占位行不进入语义树 |
| 紧凑顶栏改为非 pinned 后，顶栏随内容滚出，滚动后需回到顶部才能看到标题 | 中 | 四个页面统一 64 高；回归滚动、空态、320dp + 2x；断言滚动后标题离开视口，不遮挡列表首项 |

## 8. 测试与验收策略

- **工具链前置**：执行前确认 `/home/dev/flutter/bin/flutter --version` 与 `flutter analyze` 可运行；若 SDK 缓存不可写或工具链异常，停止并报告，不能把未执行写成通过。命令逐条读取退出码，禁止用 `| tail` 等管道末端的退出码代替；优先重定向到日志后取 `$?`。本轮复审已实测 `flutter analyze` 退出 0，三份基线测试 12 项通过；交付环境若不同，须重新验证。
- **格式**：`dart format --output=none --set-exit-if-changed lib test`。
- **静态分析**：`flutter analyze`，不允许新增 warning/error。
- **全量测试**：`flutter test`，包含本轮新增的 5 组布局与交互断言，以及既有的空态、删除确认、320dp + 2x 用例。
- **布局断言**：
  - 资产与负债金额右缘等于卡片右缘减 16，误差不超过 0.5。
  - 指标卡四张高度互差不超过 0.5；覆盖有备注与无备注两种场景。
  - 图表卡内部无 `SingleChildScrollView`；五个分类名各出现一次；趋势卡高度小于构成卡。
  - 筛选菜单包含五项，选择“支出”发出 `type=expense` 请求；触发器显示当前筛选。
  - 四个一级页使用 `LedgerSliverAppBar`：64 高、非 pinned、无 `expandedHeight`、标题 28/34 居中；滚动后标题离开视口；设置页同样使用。
  - 390 宽用于定义对齐关系；320×800 + 2x 只验证无溢出与无异常，两者不是同一挂载场景。
- **响应式**：资产、统计、流水三页与四个一级页的顶栏均在 320×800 + 2x 字体下运行，无 RenderFlex 溢出、无异常；统计页分别覆盖构成与趋势两种模式。该场景只做溢出/异常门禁，不替代 390 宽的布局矩形断言。
- **不纳入门禁**：Android 实机构建与视觉截图。项目边界规定本机不构建 Android 产物；用户安装 CI 构建包后进行视觉复核。
- **视觉基准**：实现后的排版以 `temp/uiux-fixes-demo.html` 的 `after` 状态为准；顶栏以手机框内的 64 高紧凑顶栏为准（不是 demo 页面的品牌头），并在手机框内滚动内容时随之上移。Widget 断言锁定结构，demo 只用于评审，不进入构建。
- **既有测试影响的处理**：内容高度变化可能让依赖固定滚动距离的空态用例失效，只调整测试的滚动方式，不恢复固定高度。

## 1. 背景与目标

当前记账系统在移动端使用与收支转账业务逻辑上存在以下痛点：
1. **移动端弹窗展示不全与截断**：由于使用静态视口 `max-h-[90vh]`，在移动端动态工具栏与键盘展开时，弹窗底部被截断；且操作按钮被包裹在可滚动表单底部，导致保存修改按钮不可见；二级级联分类悬浮面板在小屏下产生遮挡与触屏滚动冲突；
2. **收入记账分类逻辑混杂**：分类表未声明类型，记收入时默认选中支出分类（“餐饮美食 · 午餐”），且分类候选池混入大量日常消费分类，导致填报认知混乱；
3. **缺少账户间转账闭环**：资金在两个资产账户之间的内部划转（如银行卡转微信零钱、ATM 取现）无独立业务链路，无法在维持净资产与总资产守恒的前提下记录资金流动。

本次规划旨在系统化解决上述缺陷，实现：
- 移动端改动/记账弹窗采用现代 `100dvh` 视口高度与常驻底部操作栏，分类选择流式展开，杜绝内容截断与操作死锁；
- 收支分类体系在数据层与界面层彻底分离，记收入时严格收敛为收入专用分类与资产存入渠道，默认智能回填；
- 新增「转账」交易类型，以四段胶囊滑块、双资产账户流向、系统级转账分类自动绑定及宏观资产守恒核算构建全链路闭环。

## 2. 阶段划分

### Phase 1：数据层扩展与探针热迁移

| 项目 | 内容 |
|------|------|
| **输入** | SQLite 现有 schema、`internal/db/db.go`、`internal/server/settings.go` |
| **输出** | `categories` 表探针热迁移追加 `type` 列（`expense`/`income`/`system`）；预置系统级转账分类「账户转账」与标签「资金互转」，持久化 ID 至 `system_meta`；服务端增加 ID 级不可变守卫 |
| **验收标准** | 数据库迁移平滑幂等，老数据库零损升级；系统转账分类与标签不可被重命名或删除（严格返回 400） |

### Phase 2：后端交易契约与宏观统计核算

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 数据层支持、`internal/server/transactions.go`、`internal/server/stats.go` |
| **输出** | `transactions.go` 支持 `type = 'transfer'` 输入校验（正数金额、来源与目标均为资产渠道、双渠道互斥防自转、自动绑定系统分类）；`stats.go` 资产渠道余额公式纳管转出扣减，收支损益报表严格排除转账记录 |
| **验收标准** | 转账交易正常增删改查；转账操作前后宏观总资产与净资产维持严格物理守恒（净变动为 0）；损益趋势图与周/月收支不被转账污染；集成测试用例通过 |

### Phase 3：前端交互与移动端体验重塑

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 & 2 后端接口、`temp/frontend-demo.html`、`web/src/` 组件集 |
| **输出** | 1) `RecordModal.tsx` 改造：常驻 Footer（`flex-shrink-0 border-t`）、`max-h-[calc(100dvh-24px)]` 视口适配、四段胶囊滑块（支出/收入/转账/还款）、收支分类动态分流与内联平滑展开、转账双资产渠道网格；<br>2) `BottomBar.tsx` 扩充 5 档位筛选胶囊（全部/支出/收入/转账/还款）；<br>3) `StreamPage.tsx` 流水卡片适配转账流向展示（`[转出渠道] → [转入渠道]`）与日小计隔离；<br>4) `SettingsPage.tsx` 分类管理支持收支分段展示 |
| **验收标准** | 移动端（375px–414px）在地址栏与工具栏动态伸缩下弹窗底栏常驻可见、表单平滑自适应滚动无截断；记收入默认选中收入分类且无支出分类污染；转账选择双渠道流畅提交并正确回显；平台级虚拟键盘弹起时表单支持标准平滑滚动 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 分类收支分离机制 | 在 `categories` 表无缝追加 `type` 列（`expense`/`income`/`system`） | 根因结构归位；前后端契约统一且自解释，老数据通过迁移平滑打标 | 前端仅靠分类名称硬编码黑白名单判断（脆弱易失效，无法支撑用户自定义收入分类） |
| 转账数据流建模 | 单笔交易记录复用 `source_payment_method_id`（转出资产）与 `payment_method_id`（转入资产），`type = 'transfer'` | 与既有还款模型架构对称；单记录表达两端资金流，无冗余数据膨胀 | 拆分为一正一负两条交易（增加配对关联复杂度与死锁/孤儿记录风险） |
| 移动端弹窗截断治理 | 常驻 Flex Footer + `calc(100dvh - 24px)` 动态视口高度 | 结构化解决浏览器地址栏/工具栏动态变化下的内容比例失调，操作栏常驻表单视口底边，表单支持弹性平滑滚动（注：iOS 虚拟键盘弹起属平台级独立图层覆盖，通过标准内联滚动承接输入体验，不引入过度复杂的 visualViewport 运行时补丁） | 缩小字体与边距硬塞（破坏可读性与无障碍触摸标准） |
| 分类选择器交互形态 | 内联平滑展开（Inline Flow）代替绝对定位浮层（Cascading Flyout） | 彻底消除绝对定位浮层覆盖下方内容及小屏双重滚动条（scroll chaining）冲突 | 全屏多级跳转弹窗（增加路由层级与心智负担） |
| 转账分类标签绑定 | 自动绑定系统只读分类「账户转账 · 资金互转」，ID 写入 `system_meta` | 满足外键强约束的同时防误删改穿透，对齐还款设计，用户免选 | 允许用户随意选择普通分类（破坏资金调拨会计属性） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 老库升级时迁移与系统分类执行落点错误导致失效 | 🔴 高 | 严格约束 `migrateCategoriesColumns` 必须置于 `seed_initialized` 提前 return 分支之前（与既有热迁移并列）；`ensureSystemTransferCategory` 在 3 处分支（已初始化老库、未初始化老库、全新库）对齐调用 |
| 老库升级时已有分类的 `type` 字段历史数据兼容与纠错 | 🟡 中 | 迁移时采用 `PRAGMA table_info` 探针安全增加列，默认赋 `'expense'`，同时显式将「职业收入」更新为 `'income'`，「债务偿还」更新为 `'system'`；设置页内联编辑支持微调分类类型提供纠错途径 |
| 转账选择相同转出与转入渠道引发假转账 | 🟢 低 | 前端选择按钮自动互斥禁用同渠道；后端在 `validateTransactionInput` 强制校验 `source_id != target_id` |
| 宏观资产统计公式因加入转账而破坏守恒 | 🟡 中 | 在 `stats.go` 的单次聚合查询中，对转出方单独累加 `source_transfer_sum` 并从结余中扣减；转入方随 `tx_sum` 自然增加，单测增加守恒性断言验证 |
| 底部操作栏常驻可能挤压较小屏幕的表单可视区 | 🟢 低 | 表单主体配置 `overflow-y-auto`，移动端表单内边距适度收紧为 `p-4`，保证核心输入区滚动流畅 |

## 6. Subagent 协同规划

对照三维效益模型（任务复杂度、上下文关联度、经济与时间效益）评估本阶段委托需求：

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：数据层与探针迁移 | 强（涉及 SQLite 探针热迁移、事务与系统种子持久化） | 无（底层基石） | 主线 | 差分小且高度敏感，主线推演直接修改避免上下文缺失 |
| Phase 2：后端交易契约与核算 | 强（紧密承接 Phase 1，涉及多端点参数校验与复杂 SQL 聚合） | 无（核心业务链路） | 主线 | 资产守恒核算强依赖上下文连续性，主线处理更稳妥 |
| Phase 3：前端交互与移动端重塑 | 强（涉及 RecordModal、BottomBar、StreamPage 与 SettingsPage） | 无（依赖 Phase 2 接口定义） | 主线 | 涉及高精细度 Fluent 2 视觉令牌与触控体验，主线直接落地 |
| Phase 4：回归测试与文档维护 | 低（接口与 UI 定型后验证，只读参照） | 高（测试执行与文档更新边界自包含） | Subagent: executor | 测试与文档具备确定性验收标准，委托可保持交付专注 |

> **协同结论**：Phase 1-3 强依赖系统架构推演与上下文关联，由主线串行高效推进；Phase 4 接口与 UI 交付完毕后，可委托 Subagent: executor 执行机械验证与文档归档，或由交付段统一落地。

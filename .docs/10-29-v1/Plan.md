## 1. 背景与目标

### 现状与根因

| 编号 | 现状（截图） | 根因 |
|------|--------------|------|
| A | 记账弹层「分类与标签」把分类与标签铺成同一组胶囊：标签紧接分类下方、样式与分类完全一致，看不出「AI商品属于虚拟商品」；顶部同时存在「更换/收起」文字按钮与可点击汇总卡，两者指向同一展开态；选中标签后展开区不收起 | 分类与标签共用一套展开态，但缺少分组标题与归属表达；折叠入口重复且与汇总信息重复；缺少「选完即收」的收敛动作 |
| B | 流水页筛选是桌面式弹出菜单：菜单盖住触发胶囊与列表金额、与卡片色调几乎无差、首项高亮为直角矩形、5 个选项纵向占近半屏，弹层与触发控件没有空间关联 | 直接把 PopupMenuButton 当作移动端筛选器；菜单的定位、尺寸、材质不受页面体系约束，滚动容器内还会出现锚点错位 |
| C | 统计页只呈现服务端固定的自然月口径（本周/当月/上月/日均 + 当月构成、渠道分布 + 近 6 个月趋势），不能选日期范围，也不能按分类或标签下钻 | 统计接口只有周/月固定窗口聚合，没有区间与维度过滤契约；客户端统计页没有筛选状态，指标与图表全部绑定月度字段 |

### 本轮目标

- **记账分类标签**：拆为「分类」与「标签」两个独立字段，各自打开对应的选择面板；分类面板列出分类及其标签摘要，标签面板只列当前分类的标签；选分类自动带入该分类首个标签，选标签即回填字段；无标签时给出直达设置的出口。
- **流水筛选**：以移动端选择面板替代弹出菜单，消除覆盖触发控件、内容溢出、材质与圆角不一致的问题；当前筛选值与 48dp 触达保持不变。
- **统计区间筛选**：统计页顶部显示当前口径摘要与「筛选」入口；面板内统一编辑日期范围（本周/本月/上月/近 30 天/自定义）、分类与标签，草稿点「应用」后生效；指标、构成、渠道分布、趋势全部按所选范围与维度重新聚合。
- **构件复用**：选择面板壳与选项行收敛为共享构件，记账分类/标签与流水筛选直接复用；统计筛选面板沿用同一标题、内边距、安全区与底部操作行约定，避免各页各写一套。

### 明确的范围外

- 不改 Web 端界面：统计区间筛选是 Android 客户端能力，新端点为增量接口，既有 `/api/stats/summary` 契约与数值口径不变，Web 继续消费原有接口。
- 不把区间统计写入本地冷启动快照（快照仍只保存配置、流水、月度汇总）；统计页冷启动改为骨架加载。
- 不改流水页的日期范围与筛选维度（仍只有全部/支出/收入/转账/还款）。
- 统计筛选为单选（一个范围 + 一个分类 + 一个标签）；不做多分类/多标签并集，也不做跨维度组合矩阵。
- 不保留记账分类区的内联展开形态：分类与标签不再共用同一展开块。
- 不改资产负债口径、不做导出、不做多区间对比、不引入第三方图表或日期库（日期选择使用 Flutter 内置 `showDateRangePicker`）。
- 不调整版本号与发布流程；是否发版由用户决定。

## 2. 阶段划分

### Phase 1：后端区间聚合与筛选契约

| 项目 | 内容 |
|------|------|
| **输入** | 既有 `/api/stats/summary` 的聚合函数（按类型汇总、分类/标签构成、渠道分布、月度趋势）与分类统计排除口径 |
| **输出** | 统计聚合支持可选的分类/标签过滤；新增按日期区间聚合的统计端点，返回区间收支、结余、已过天数、上期对比、笔数、分类/标签构成、渠道分布与截至区间末月的 6 个月趋势；参数非法时返回 400 |
| **验收标准** | 不传过滤参数时既有汇总接口数值与现状完全一致；区间端点对固定测试时钟返回可精确断言的数值；分类过滤、标签过滤、统计排除分类、非法参数四类场景均有用例；移除过滤条件后对应用例失败 |

### Phase 2：客户端统计数据层

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 的区间端点契约、既有模型/客户端/控制器约定 |
| **输出** | 区间统计模型与查询值对象；API 客户端按查询构造请求；控制器持有查询状态、区间结果与加载/错误态，带请求代际；全量加载、记账变更、渠道变更后同步刷新，配置刷新后剪枝失效的筛选维度并按需重载 |
| **验收标准** | 默认查询为「本月 1 日至今天」；查询变化只保留最后一次响应；401 走既有会话过期链路；删除正在筛选的分类/标签后筛选维度被剪枝并重新请求，新增与重命名不产生额外请求；既有控制器与缓存用例不回归 |

### Phase 3：共享选择面板与记账双字段

| 项目 | 内容 |
|------|------|
| **输入** | 现有记账弹层分类区、分类与标签数据模型、设置页的标签管理入口 |
| **输出** | 可复用的选择面板（标题、48dp 选项行、选中勾选、安全区、可滚动）与选项行构件（记账与流水直接复用，统计筛选沿用同一视觉约定）；记账弹层的「分类」「标签」两个独立字段，分别打开分类面板与标签面板；分类面板只列当前表单类型的分类并显示其标签摘要，标签面板只列当前分类的标签；选分类自动带入首个标签；无标签时面板内提供「前往设置」；转账/还款保留原只读系统分类行 |
| **验收标准** | 表单内不再有内联展开的分类区，改为两个字段行；点分类字段只弹出分类面板，点标签字段只弹出标签面板；支出单据的分类面板不出现收入分类；分类行显示标签摘要；选分类后标签字段自动更新为该分类首个标签；标签面板只包含当前分类的标签；转账/还款仍显示只读系统分类行；320dp + 2 倍字体下字段行与面板均不溢出；编辑既有账单时仍显示原分类与标签 |

### Phase 4：流水筛选与统计筛选面板

| 项目 | 内容 |
|------|------|
| **输入** | Phase 2 的查询状态与区间结果、Phase 3 的选择面板与选项行构件、流水页筛选入口、统计页现有指标与图表 |
| **输出** | 流水筛选改为选择面板；统计页顶部「口径摘要 + 筛选」入口与单一筛选面板：范围预设与自定义日期、分类、按所选分类联动的标签；面板只返回草稿查询，由统计页在关闭后统一提交并同步视角，「重置」回到默认；指标、构成环图（含标签下钻）、渠道分布、趋势全部改读区间结果；口径摘要随应用更新；请求失败时内容区显示错误与重试 |
| **验收标准** | 流水筛选打开后面板完整可见、选择即生效并关闭、320dp + 2 倍字体不溢出；统计默认口径为「本月 · 全部维度」；面板内改范围/分类/标签后未点应用不改变页面数据与摘要，点应用后请求参数与摘要同步，关闭面板不生效；标签区在未选分类时给出提示、选分类后只列该分类标签；跨类型分类应用后自动切换到对应视角；维度筛选生效时 Hero 徽标显示笔数而不是储蓄率；请求失败时显示错误与重试、不残留上一次的数字；无数据时显示空态而不是错误；指标卡等高且四卡不溢出 |

## 3. 关键决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 分类标签呈现 | 两个独立字段（分类、标签），各自打开对应的选择面板 | 分类与标签在表单上就是两个不同的必填维度，分开呈现让层级一眼可辨；每个面板只承担一个维度的选择，标签面板天然按当前分类收敛；用户已明确选定该方案 | 单入口 + 内联二级分组（方案 A：信息集中、点击数少，但分类与标签仍共处一个展开块，评审认为层级不够直接）；整块改为全屏选择页（打断记账上下文） |
| 字段入口 | 分类字段 → 分类面板；标签字段 → 标签面板，两行常驻表单 | 每个入口只对应一个维度，不存在重复折叠入口；字段值常驻可见，收起/展开状态被消除 | 同一入口内切换两个层级（指代含糊，回到现状问题）；标签复用分类面板（多一次维度切换） |
| 选分类后的标签 | 选择分类后自动带入该分类首个标签 | 记账要求分类与标签必填，自动带入避免保存时的中间非法态；用户可再进标签面板改选 | 仅设置分类并把标签置空（保存前需额外拦截与提示） |
| 分类面板内容 | 只列当前表单类型的分类（沿用 `_categoriesForType()`），每行显示分类名与标签摘要 | 表单类型已由分段控件决定；跨类型列出会让支出单据存下收入分类——客户端只校验分类非空、服务端只校验分类存在，统计按 `type` 聚合后同一笔钱在支出与收入两侧对不上。限定类型后列表更短，层级更清楚 | 同列支出/收入两组（可写入错误数据）；只显示分类名（用户选分类时看不到其下标签） |
| 流水筛选容器 | 底部选择面板（modal bottom sheet） | 移动端标准选择容器；不受锚点定位影响，不会覆盖触发控件；材质与页面体系一致 | PopupMenuButton（现状，覆盖与错位）；常驻横向胶囊（占首屏高度且 2 倍字体需横滚）；DropdownMenu（同样存在锚点与宽度问题） |
| 统计口径来源 | 新增区间端点，统计页只消费区间结果 | 固定月/周字段无法表达任意区间与维度过滤；新增端点保住流水头条、资产页与 Web 的既有月度契约 | 客户端用流水列表自行聚合（接口只给 100 条，必然漏数）；把 summary 字段改成区间语义（流水头条与 Web 同步受污染） |
| 筛选粒度 | 范围 + 单个分类 + 单个标签（单选）；标签隐含其所属分类 | 个人记账的常见诉求是「某段时间某个分类/标签花了多少」，单选即可回答且面板与请求都简单 | 多选（需要 IN 查询、已选条件管理与取消入口，超出需求，交互成本高） |
| 过滤语义 | 全量过滤：区间收支、构成、渠道、趋势同一口径；维度筛选生效时 Hero 徽标由储蓄率改为笔数 | 用户选标签就是想知道该标签的钱花在哪；口径分裂会出现同页数字互相矛盾；单维度下储蓄率恒为 0 或 100%，没有解释力 | 只过滤构成图（汇总仍是全量，误导）；保留储蓄率（数字自洽但语义失真） |
| 分类/标签与视角 | 统计筛选面板同时列出支出与收入分类；应用的分类或标签属于另一类型时，页面把视角切到对应类型 | 记账侧类型由分段控件决定、无需切换；统计侧必须先能选到收入维度，否则用户要关面板、切视角、再开面板 | 统计只列当前视角的分类（多两次往返，且面板遮住视角切换控件） |
| 上期对比 | 将区间按日历月整体前移一个月并夹取月末（如 10-01~10-31 → 09-01~09-30） | 月度选择时符合「上月同期」直觉；任意区间也有确定语义 | 等长前移窗口（10 月会对比 8-31~9-30，差一天，用户费解）；不显示对比（丢失环比） |
| 指标卡 | 本期（含较上期注脚）、日均（按已过天数）、上期、单笔均额（注脚为笔数） | 全部是区间可解释的金额指标，保留四卡等高的既有布局 | 保留本周/当月/上月（与自选区间语义冲突） |
| 日期选择 | 预设（本周 = 周一~今天；本月 = 1 日~今天；上月 = 上月整月；近 30 天 = 含今天共 30 天）+ 内置 `showDateRangePicker` | 常用范围一键可达且边界唯一确定；自定义走系统组件，零新依赖 | 只给日期选择器（每次都要点日历）；自绘日历（重复造轮子） |
| 统计筛选入口 | 顶部「口径摘要 + 筛选」行，点开后是单一面板，统一编辑范围/分类/标签 | 只保留一个入口，不占用三行控件；摘要行常驻显示当前口径，弥补面板收起后的可见性；用户已选定该方案 | 三个常驻胶囊（方案 A：改一个维度快，但控件占位多且筛选入口分散）；AppBar 下拉菜单（锚点与尺寸问题） |
| 草稿与应用 | 面板内改动只写入草稿，点「应用」时 `Navigator.pop` 返回查询值，由统计页在面板关闭后统一提交并同步视角；关闭面板不生效；「重置」回到默认草稿 | 三个维度一次确认，避免每改一项就发一次请求与刷新页面；面板不持有控制器，「未应用不请求」是结构保证 | 即时生效（面板内每点一次就刷新统计，闪烁且请求多）；逐项确认（入口层级过深） |
| 标签筛选前置分类 | 统计面板内标签区跟随草稿分类；未选分类时只提示「选择分类后可筛选标签」 | 标签名可能在不同分类下重复，先有分类才能确定标签语义；与分类面板的层级一致 | 平铺全部标签（跨分类同名歧义、列表过长）；标签独立于分类（需要额外的冲突处理） |
| 区间统计缓存 | 不写入冷启动快照 | 查询组合多、缓存键会膨胀；区间结果秒级可取，冷启动用骨架即可 | 按查询缓存（键组合膨胀、失效复杂，收益有限） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 区间按服务端本地日界切分，客户端时区不同会导致边界日偏移 | 中 | 与现有月度统计保持同一时区约定；接口只接收 `yyyy-MM-dd`，服务端按本地日界解析；用例含本地 10-01 00:30 的交易，若按 UTC 解析会落到 9 月并让断言失败 |
| 统计页冷启动从「缓存即时渲染」退化为骨架 | 中 | 仅统计页受影响，流水/资产/设置仍走缓存；冷启动用例改为按可见的流水页断言，不把离屏统计骨架当回归 |
| 过滤与视角不匹配导致空页 | 中 | 应用后页面按所选分类的类型切换视角；空态文案覆盖构成与渠道两处 |
| 上期口径与用户直觉不一致 | 中 | 统一前移一个日历月并夹取月末；文案用「上期」；集成测试断言精确金额 |
| 删除正在筛选的分类/标签后查询仍带失效 ID，区间结果归零而摘要还显示旧名称 | 中 | 配置刷新成功后剪枝失效的筛选 ID 并重新请求；用例断言删除分类后摘要回落为「全部维度」、删除标签后只剩分类 |
| 统计筛选面板在 320dp/2 倍字体下溢出，或摘要行被长范围文案撑破 | 高 | 面板内容可滚动、摘要行用 Wrap/两行截断、选项行 48dp 起；补 320dp + 2x 用例 |
| 记账弹层上再叠加选择面板，返回层级或遮罩处理不当 | 中 | 记账、流水、统计复用同一选择面板实现（Phase 3 产出，自带遮罩与安全区），面板只 pop 自身；返回键逐层关闭，不穿透到记账弹层 |
| 统计筛选草稿被关闭后用户误以为已生效 | 中 | 「应用」为面板底部主按钮；关闭/返回不提交；摘要行只在应用后变化；用例断言未应用时请求数不变 |
| 双字段比内联展开多一次面板往返 | 低 | 分类面板显示标签摘要、选分类自动带入首标签，常见路径仍是「点分类 → 选 → 保存」 |
| 替换流水筛选影响其他菜单（行内更多操作） | 低 | 只替换筛选入口；行内菜单保持 PopupMenuButton 与既有裁剪；保留其裁剪断言 |
| 统计测试依赖运行时时钟 | 中 | Go 侧冻结 `nowFunc`；Flutter 侧从 `DateTime.now()` 派生期望参数，断言格式与相对关系而非硬编码日期 |
| 区间端点误用全量口径（过滤漏加、趋势漏过滤） | 高 | 聚合函数只保留一份过滤入口；用例同时断言汇总、构成、渠道与趋势在过滤后的数值 |
| 旧服务端无新端点时客户端报错 | 低 | 同仓库同版本部署；错误走统计页错误态并可重试 |
| 本机无 Android 工具链，视觉验收只能靠 CI 与 Web/静态 Demo | 中 | 门禁以 `flutter analyze/test` 为准；Demo 与 320dp/2x 用例兜住布局；真机效果由用户装包复核 |

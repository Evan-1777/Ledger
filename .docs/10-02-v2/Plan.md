## 1. 背景与目标

在 10-02-v1 交付归档后，经双模型联合复审，发现若干需修复的具体问题与健壮性短板：
1. `Navbar.tsx` 中使用未定义的 Tailwind `xs:inline` 死断点，导致桌面端与移动端登出按钮中的“登出”文本均被隐藏；
2. `SettingsPage.tsx` 中调序操作通过 `Promise.all` 并发调用更新，各更新内部均独立触发 `fetchConfigData()`，存在双重网络请求乱序与界面竞态闪烁风险；且对于断号列表的调序需更贴合已有序号结构；
3. `SettingsPage.tsx` 中内联重命名未对 `onUpdateCategory` / `onUpdateTag` 抛出的异常进行 `try...catch` 兜底，导致错误时控制台出现 Unhandled Promise Rejection 并异常关闭/卡死状态；
4. 重命名未在前端对同级项进行同名预校验，后端唯一约束冲突直接透出英文报错信息，破坏全中文 UI 一致性；
5. `RecordModal.tsx` 滑块位移使用 `left` 属性硬编码过渡，触发重排且未走 GPU Compositor 硬件加速通道；
6. `index.css` 的 `.dark-mode` 未定义 `--color-expense-stroke` 与 `--color-income-stroke`，暗色模式下回退至高亮浅色边框，破坏暗色模式一体感。

本次计划以工程纪律（最短有效差分、结构归位、拒绝过度设计）为准绳，实现以下目标：
- 将登出按钮文字断点规范为 `hidden sm:inline`，小屏仅留图标，桌面端恢复图文完整展示；
- 在 `App.tsx` 集中提供安全调序链路，串行执行更新并在完成后单次拉取数据，消除并发网络竞态；调序优先对换已有序号，相等时递增打破死锁；
- 在内联重命名中补齐同级重名预拦截与 `try...catch` 兜底，优化错误提示为清晰中文；
- 滑块指示器改用 `transform: translateX` 驱动，实现像素对称与 GPU 硬件加速；
- 补齐暗色模式语义边框令牌，保证 Fluent 2 暗色深度一致。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 调序数据流归位 | `App.tsx` 提供单一 `handleReorderCategories` | 结构源头归位：将多次变更与数据刷新生命周期聚合在数据源层，仅拉取一次，杜绝子组件并发碎片调用 | 在子组件内手写复杂超时防抖（补丁式拦截，逻辑分散脆弱） |
| 滑块位移动画 | `left-1 w-[calc(50%-4px)]` + `translate-x-full` | 数学对称精确（左右均为 4px 内距），纯走 Compositor 硬件加速，零 Reflow | 继续使用 `left-[calc(50%+2px)]`（经验值拟合，每帧触发重排） |
| 重命名冲突防御 | 前端轻量查重 + 后端异常中文本地化双重守卫 | 前端即时响应提升体验，后端中文兜底杜绝英文外漏 | 引入复杂表单校验库（违背 YAGNI，增添非必要依赖） |
| 临时 Demo 文件管理 | 保持既有状态并确认 gitignore 规则 | `AGENTS.md` 明确规定为 Frontend 扩展产物，未在 `.gitignore` 忽略，符合流程 | 误信审计虚假陈述盲目执行 `git rm --cached`（非必要扰动） |

## Phase 2：账目流水页结构重塑

### TASK-004：重建日分组容器与表头

- **Status**：DONE
- **Executor**：主线
- **Description**：在 `web/src/pages/StreamPage.tsx` 中将日期分组由「多张独立浮起卡片」重构为「单个连续表面 + 表头行 + hairline 分隔行」。
- **Details**：
  - 每个日期分组渲染为一个容器：卡片面底色、1px 中性描边、`rounded-xl`、统一投影；
  - **容器禁止设置 `overflow: hidden`** —— 行内二级操作浮层为绝对定位且须溢出日容器边界（末行、单笔分组场景），一旦裁剪将导致「删除账单」项被硬截断且不可点击；容器圆角改由内部元素承担：表头声明顶部圆角（略小于容器以贴合 1px 描边）、组内末行声明底部圆角，悬停底色由此自然填充而不外溢；
  - 表头行独立成层：凹陷面底色 + 底部 1px 分隔线，左侧为日期标签，右侧为当日支出 / 收入小计；
  - 日期标签保留现有 `今天` / `昨天` / `M月D日` / 跨年 `YYYY年M月D日` 判定逻辑，**不改动跨年补齐规则**；
  - **星期为新增派生字段**：复用现有 `dateStr.split('-')` 分段结果，以 `new Date(year, month - 1, day)` 构造**本地时区**日期对象后取星期，映射为 `周一`…`周日`，以次级弱化文本（11px、三级前景色）紧跟主日期标签右侧；
  - **禁止使用 `new Date(dateStr)` 直接解析分组键** —— 该形式在 ECMAScript 中被规范化为 UTC 零点，UTC 以西时区会回退至前一天导致星期错位；现有 `getDayLabel` 已采用分段 `parseInt` 模式，星期派生须与之同构；
  - **表头日期标签为「主标签 + 副文本」两段式**：主标签沿用现有 `今天` / `昨天` / `M月D日` / 跨年 `YYYY年M月D日` 判定逻辑不变；副文本为 `M月D日` 与星期（`今天 10月4日 周日`、跨年时主标签已含年份，副文本仅取 `M月D日` + 星期），避免主标签为 `今天` / `昨天` 时丢失日期信息；
  - **表头容器允许换行**（`flex-wrap` + 纵向小间距）：`main` 容器 `px-5` 与表头自身内边距叠加后，320px 视口下内容净宽约 248px，当日收支并存时左右两组内容约需 295px —— 固定单行必然碰撞挤压；允许换行后小计整体折至第二行，日期标签与小计在任意窄度下均完整可读；
  - 表头右侧小计沿用现有排除还款 / 转账的聚合结果，**不改动计算逻辑**；无支出或无收入时不渲染对应项；
  - 组内各行之间以 1px 中性分隔线区隔，替代原有的卡片间隙；末行与表头之间同样由表头底边线区隔；
  - 移除原有的「N 笔」数量胶囊 —— 该计数在连续表面内已由行数自然表达，属界面噪声。
- **Acceptance Criteria**：
  - 同一日多笔账单呈现在同一连续表面内，日维度一眼可辨；
  - 表头日期、小计与现有实现语义完全一致（含跨年场景）；
  - 小计严格排除还款与转账（以既有回归用例验证）；
  - 单日仅一笔账单时排版不塌陷；
  - 320px 视口下表头日期标签与收支小计不碰撞（小计折行完整可读）；
  - 星期在本地时区下与实际日期一致（东八区与 UTC-5 均正确）。

### TASK-005：重构行内信息结构与类型编码

- **Status**：DONE
- **Executor**：主线
- **Description**：将单行重构为「类型图标块 + 描述与元信息 + 定宽金额」三段式，移除彩色分类胶囊，改用形状编码类型、色彩仅由金额承担。
- **Details**：
  - **类型判定必须保留现有兼容分支**：`item.type === 'expense' || (!item.type && item.amount_cents < 0)` 与对应的收入分支、`isNeutral` 判定均原样保留 —— 虽然 `transactions.type` 为 `NOT NULL DEFAULT 'expense'` 且迁移时已按金额符号回填、前端 `Transaction` 类型亦声明为必填，但既有代码的这层兜底是**存量老库在迁移异常场景下的唯一显示保障**，本次为视觉重构而非契约变更，不得借机删除既有防御；
  - 行首为 32px 圆角方形图标块（`rounded-lg`），底色与描边色按类型映射：支出用支出语义色系、收入用收入语义色系、转账与还款用品牌色系；内部渲染 Phase 1 新增的 `ExpenseIcon` / `IncomeIcon` / `TransferIcon` / `RepaymentIcon`，颜色随容器 `currentColor`；
  - 中间为两行文本：首行用途描述（主色、medium 字重、单行省略），次行元信息（次级色）：`分类 · 标签 · 账户 · 时间`，转账与还款在账户位渲染 `转出 → 转入` 流向；
  - **元信息必须完整包含 `item.tag_name`（细分标签）** —— 原型早期版本曾遗漏该段，现已补齐为四段；渲染时按「分类 · 标签 · 账户 · 时间」顺序以中点连接，**任一分段为空时不得产生连续中点或首尾悬空中点**；
  - **元信息行保持完整四段，不得按视口宽度隐藏任何分段** —— 整行依托弹性约束与单行省略自然截断即可；窄屏隐藏分类会迫使用户在主画布无法判断消费归属，须打开模态窗才可获知，直接破坏核心对账体验（且底部筛选仅按交易大类分流，不存在分类维度，无法替代）；
  - 移除原有的分类·标签彩色胶囊标签、逐行时钟图标与 `opacity-40` 分隔符点 —— 图标承载时间属冗余，分隔符点改用三级前景色以降低视觉噪声；
  - **金额字符串契约固定为 `${sign}¥${amount}`**：支出为 `−¥268.40`、收入为 `+¥8,000.00`、转账与还款为 `¥2,000.00`（中性无符号）；`¥` 符号对全部类型一律出现并置于符号之后、金额之前，千分位使用 `toLocaleString` 生成 —— 现有实现中支出 / 收入无 `¥` 而中性有 `¥`，属不一致，本次统一消除；
  - 金额段：`min-w` 定宽 + 右对齐 + `tabular-num`，字号提升为主信息级，符号沿用对应语义色；
  - 行悬停态为底色过渡（复用悬停面色），**移除现有的 `hover:-translate-y-[1px]` 位移动效** —— 位移会使整列表产生抖动，且破坏连续表面的平整感。
- **Acceptance Criteria**：
  - 单行色彩焦点唯一（金额），类型可通过图标形状辨识；
  - 金额列在任意行数下竖向对齐；
  - 转账 / 还款的账户流向完整可读；
  - 长描述与长账户名正确省略，不挤压金额与操作区；
  - 列表悬停无位移抖动。

### TASK-006：行内操作收敛为二级浮层

- **Status**：DONE
- **Executor**：主线
- **Description**：将每行常驻的「编辑 + 删除」双图标按钮收敛为单个多操作入口，点击后在行内展开二级浮层。
- **Details**：
  - **必须以 React 声明式状态实现，禁止照搬原型的命令式 DOM 操作**（原型为纯静态 HTML，用 `toggleFlyout` 直接增删节点；React 中照搬将破坏虚拟 DOM  reconciliation）：
    - 状态为 `const [openMenuTxId, setOpenMenuTxId] = useState<number | null>(null)`，以账单 `id` 标识唯一展开行（天然互斥，同一时刻至多一个浮层展开，无需额外布尔量）；
    - 渲染时以 `openMenuTxId === item.id` 判定该行浮层是否挂载，并同步驱动触发按钮的 `aria-expanded`；
    - 浮层容器使用 `position: relative` 单元格包裹，浮层本身绝对定位，**禁止使用 portal 或会脱离滚动容器的定位方式**；
  - 行尾渲染单个 `MoreVerticalIcon` 按钮（26px 命中区），带 `title`、`aria-label`、`aria-haspopup` 与 `aria-expanded`；
  - 点击展开二级浮层，含「编辑账单」与「删除账单」两项，沿用设置页既有的浮层视觉与 `z-30` 层级约定；破坏性项使用支出语义色；
  - 触发按钮在浮层展开期间保持激活态（底色 + 主色前景 + 不透明），关闭时复原；
  - 浮层关闭条件：点击浮层外部、再次点击同一入口、按 `Escape`、切换日期分组；
  - **点击「编辑账单」或「删除账单」触发 `onEdit` / `onDelete` 回调时，必须在同一处理函数内先 `setOpenMenuTxId(null)` 再执行回调** —— 删除操作会触发确认对话框并在确认后整表刷新，浮层若未同步重置将残留悬空按钮；
  - 文档级外部点击与 `Escape` 监听须在 `useEffect` 中注册并正确清理，依赖项变化时不得重复绑定；
  - 打开浮层时阻止事件冒泡，避免触发文档级外部点击监听导致立即关闭；
  - 桌面端悬停行时入口显现，触屏与键盘可达（`focus-visible` 态可见，入口不得因缺少 hover 而不可达）；
  - 复用页面既有 `EditIcon` / `TrashIcon` 作为浮层项的语义前缀，或按设置页浮层范式保持纯文字项 —— 二者择一，与既有设置页浮层保持同构。
- **Acceptance Criteria**：
  - 行内常态元素压缩至一个操作入口；
  - 浮层四项关闭条件均生效，触发按钮激活态随开合正确切换；
  - 删除操作仍触发既有确认流程与回调；
  - 浮层可自由超出日容器边界（末行、单笔分组场景下「删除账单」完整可见可点击），并以 `z-30` 悬浮于相邻日分组之上；
  - 键盘可聚焦入口并打开浮层。

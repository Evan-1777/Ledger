**状态**：DONE  
**日期**：2026-10-01  
**版本**：v1.0  
**回归测试结论**：全部后端单元测试与集成测试通过，前端 TypeScript 校验与生产打包通过，单二进制独立运行验证通过（含 SPA 路由回退、静态资源直出与 `/api/health` 接口正常响应）。

---

## 1. 背景与目标

Ledger 定位为轻量、高颜值、个性化的个人记账 Web 应用，未来部署于个人 PC 或个人 VPS（Docker Compose）。  
为了保障后续个性化业务开发的纯粹性与高扩展性，本次规划仅交付规范、干净、工业级的工程骨架与配置：
- 后端采用 Go 标准库与轻量模块化结构，集成纯 Go SQLite 驱动（无 CGO 依赖，利于跨平台与容器轻量分发）；
- 前端采用 React + Vite + Tailwind CSS + TypeScript，配置前后端联调反向代理；
- 通过 Go `embed.FS` 将前端静态资源嵌入 Go 单二进制，提供零外部运行时依赖的单文件交付能力；
- 保持极简设计（YAGNI / Ponytail 原则），杜绝未经验证的复杂抽象与业务臆测。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 后端语言 | Go 1.27 | 静态编译、极低内存占用、天然支持跨平台单二进制交付 | Node.js/Python（运行时环境复杂，镜像体积大） |
| SQLite 驱动 | `modernc.org/sqlite` | 纯 Go 实现，无 CGO 依赖，支持极简交叉编译与 Docker 轻量部署 | `mattn/go-sqlite3`（需 CGO/gcc，跨平台与容器多阶段构建麻烦） |
| 前端构建工具 | Vite + React + TypeScript | 现代化构建体验、极速 HMR、生态健全且轻量 | Next.js/Webpack（过于厚重，引入不必要的 Node SSR 复杂度） |
| 样式方案 | Tailwind CSS | 原子化、轻量高灵活度，便于后续个性化高颜值 UI 扩展 | CSS-in-JS / 重型组件库（增加样式运行时开销并限制自定义） |
| 资源分发 | Go `embed.FS` + SPA 回退 | 彻底打通单文件独立运行，无缝兼容前端客户端路由 | 外部静态目录映射（部署分散，破坏单二进制便携性） |
| 任务与构建编排 | Makefile | 标准统一、依赖透明，覆盖 dev/build/test/clean | 复杂自制脚本（增加维护心智负担） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 前端未构建时 Go `embed` 失败 | 🟡 中 | 在 `web/` 内维护防空占位机制，并在构建脚本中确保 build 前端先行 |
| SPA 客户端路由与 API 路由冲突 | 🟡 中 | 明确 `/api/` 路由优先级，非 API 且非静态文件请求回退至 `index.html` |
| SQLite 并发锁冲突 | 🟢 低 | 初始化强制开启 WAL 模式，配置适度连接池与 BusyTimeout |

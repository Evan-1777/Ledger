## 1. 背景与目标

### 现状与根因

| 编号 | 现状 | 根因 |
|------|------|------|
| A | 冷启动先显示启动页，直到 `/api/auth/check` 返回才进入 Shell；网络失败停在启动页并提供重试 | 启动链路把「网络校验凭证」当作进入应用的前置条件，本地已保存的会话无法直接使用 |
| B | 登录后四个一级页先显示骨架，直到分类、流水、统计三路请求全部返回 | `LedgerController` 每次启动都从空状态发起加载，页面只能以「加载中且无数据」呈现骨架 |
| C | 进程被杀后所有业务数据丢失，下一次冷启动重复 B | 数据只驻留在内存，没有可复用的「上一次成功同步」本地读模型 |
| D | 断网冷启动无法查看任何已同步数据 | A 与 C 叠加：既不信任本地会话，也没有本地数据 |

### 本轮目标

- **首帧即内容**：本地存在有效 token 与上次同步快照时，冷启动第一帧直接进入 Shell，流水、统计、资产、设置四个一级页立即呈现缓存数据，不出现空白或骨架。
- **后台再验证**：首帧构建前启动会话校验与配置、流水、统计刷新，结果返回后更新内存并写回本地；任一域成功即保鲜，失败保留该域旧数据。
- **鉴权同构**：有 token 即乐观进入；后台返回 401 时清除 token、清空内存并回登录页；网络/超时失败保留会话并继续展示缓存快照，由既有刷新错误提示暴露连接问题。
- **无缓存可退化**：首次安装、无 token、缓存损坏或服务地址变更时，行为退化为现有登录页或骨架加载路径。
- **零后端改动**：不改 Go API、SQLite、Web React；仅 Flutter 客户端。

### 明确的范围外

- 离线写入、离线队列、冲突合并、后台同步、推送。
- 流水分页或扩大 100 条窗口。
- 缓存加密、按账号多租户隔离。
- Web 端界面行为调整（缓存代码平台中立，Web 自检自动继承）。

## 2. 阶段划分

### Phase 1：可序列化的本地只读缓存层

| 项目 | 内容 |
|------|------|
| **输入** | 现有 API 模型、`shared_preferences` 依赖、会话已保存的服务器地址 |
| **输出** | 配置（分类+渠道）、流水、统计三个域的 JSON 缓存读写；版本与服务地址标记；损坏/不匹配数据静默丢弃；模型双向序列化 |
| **验收标准** | 三域写入后读回与写入前结构一致；换服务器地址读取返回空；损坏 JSON 返回空且不抛异常；未引入新依赖；静态分析无告警 |

### Phase 2：控制器缓存恢复与成功写穿

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 的缓存层、`LedgerController` 三路加载器 |
| **输出** | 首帧前的水合入口；每个域加载成功后写回对应缓存；失败路径不覆盖缓存；流水筛选态结果不污染全量缓存 |
| **验收标准** | 水合后数据就位且不进入 loading；`loadAll` 成功后三域各写一次；请求失败时内存与缓存均保留旧值；筛选态刷新不写流水缓存 |

### Phase 3：会话乐观恢复与后台校验

| 项目 | 内容 |
|------|------|
| **输入** | `SessionController`、应用入口与启动页 |
| **输出** | 本地 token 存在即进入 authenticated；后台校验 401 回登录、网络失败保留会话；请求代际防止旧校验结果影响新会话；删除品牌启动页，booting 仅保留最小进度指示 |
| **验收标准** | 有 token 时 `restore` 不等待网络即返回 authenticated；后台 401 清除 token 并 locked；后台断网保持 authenticated 且 token 保留；无 token 直接 locked；`_SplashScreen` 与 `startupError` 无残留 |

### Phase 4：首帧装配、冷启动回归与交付

| 项目 | 内容 |
|------|------|
| **输入** | 前三阶段的缓存、控制器与会话能力 |
| **输出** | 生产入口注入真实缓存；应用在首帧构建前水合并启动刷新；登录转换时再次水合；冷启动/断网/401/无缓存的 Widget 回归；版本与文档；归档与提交 |
| **验收标准** | 生产入口确实构造并传入缓存；有缓存时冷启动首帧可见流水且无骨架；无缓存时首帧仍为骨架，不出现假空态/错误态；断网刷新后数据仍在、停留 Shell 并出现一次错误提示；401 回登录且不再显示业务数据；格式、分析、全量测试通过；文档与实现一致；归档目录同时含 Plan 与 Tasks；提交仅含本轮路径 |

## 3. 关键决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 缓存介质 | `shared_preferences` 中按域存 JSON | 已有依赖、Web/Android 通用、可在首帧前同步读取；数据量受 100 条流水窗口约束 | 新增 SQLite/文件库（新依赖、平台分支、启动异步）；安全存储存大块 JSON（读写慢、非设计用途） |
| 缓存粒度 | 配置、流水、统计三个独立条目 | 三路请求成功/失败互相独立，部分成功只更新对应域；损坏影响面小 | 单一整包快照（任一路失败就无法保存，容易把半新半旧写成一体） |
| 写入时机 | 控制器每个域成功后写穿 | 冷启动、下拉刷新、记账/设置变更后都会自动保鲜；失败路径天然不写 | 退出时统一写（异常退出丢失）；定时写（无收益、增加状态） |
| 首帧刷新时机 | 水合后同步启动三域加载，不推迟到 post-frame | 三个 loading 标志先于首帧构建置位；无缓存时保持骨架，不闪假空态/错误态 | post-frame 启动（已核实首帧会误显示空态与错误态） |
| 登录转换 | 再次水合缓存后再刷新 | 401/退出会清空内存；不再水合会让重新登录以骨架面对同一份磁盘数据 | 仅冷启动水合（少一次调用，但同一语义断裂） |
| 启动页 | booting 仅保留最小进度指示，删除品牌启动页 | 入口已 await restore，品牌启动页在首帧前不可达；删除不可达 UI | 保留完整启动页（约 50 行不可达代码） |
| 缓存版本 | 信封保留 version=1，读取时校验 | 容忍式 fromJson 会把字段变化读成默认值，版本提供整体失效契约 | 去掉版本（未来字段语义变化可能静默串读） |
| 流水筛选 | 仅当筛选为「全部」时写流水缓存 | 服务端按筛选返回子集，直接写入会让下次冷启动把子集当作全量 | 缓存筛选态并在启动恢复（启动应展示全量，且增加状态） |
| 会话恢复 | 本地 token 存在即乐观进入，后台校验 | 消除网络对首帧的阻塞；401 能快速纠正；断网仍可查看已同步数据 | 继续先校验（原缺陷）；校验失败一律回登录（断网时缓存永远不可见，与首条目标冲突） |
| 鉴权失败语义（2026-10-21 用户确认） | 401 → 清 token 回登录；网络/超时 → 保留会话并展示缓存快照 | 凭证被拒是确定性失败；网络失败不代表凭证失效。否则「失败保留旧数据」在离线场景无法成立 | 任何失败都回登录（离线不可用）；任何失败都保留（凭证失效时不纠正） |
| 缓存作用域 | 条目内记录服务器地址，读取时精确匹配 | 换服务器后不会把旧账本数据渲染到新服务器上下文 | 全局单缓存（切服后串数据）；按地址分键（多份冗余，仍需清理） |
| 退出/过期后的缓存 | 保留磁盘缓存，内存清空，锁定页不渲染 | 再次登录可继续首帧秒开；单用户个人设备，token 仍在系统安全存储 | 退出即删缓存（牺牲再次登录的首帧体验；401 过期也会误删） |
| 旧数据提示 | 复用既有 SnackBar 与错误态，不新增「离线/已缓存」常驻标识 | 刷新失败已有一次性提示；常驻标识属于新界面语义，需求未要求 | 顶部离线横幅/时间戳（新增界面噪音与状态） |
| 版本 | `0.2.0+4` | 新增用户可感知行为，按次版本号递增；本轮不推 tag、不触发 Release | 保持 0.1.2（行为变更与版本不一致）；直接发 0.1.3（新能力按补丁号不合理） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 乐观进入会在 token 已被吊销时短暂展示缓存数据 | 中 | 仅在本地 token 存在时进入；后台校验立即执行；401 立刻清 token、清内存并回登录；缓存按服务器地址隔离 |
| 财务数据以明文 JSON 存在普通偏好存储 | 中 | 单用户个人设备；锁定页不渲染；token 仍在安全存储；不缓存密码/密钥；后续如需更高保护可迁移到加密存储 |
| `shared_preferences` 整键读写随数据增长变慢 | 低 | 流水固定 100 条窗口，快照约几十 KB；缓存类注释写明上限与迁移到 SQLite/文件的升级路径 |
| 首帧前同步解析缓存增加启动耗时 | 低 | 三个键各自解析，未命中直接返回；解析失败静默降级为骨架；实测纳入冷启动测试 |
| 测试替身注入缓存，生产入口漏接线，门禁全绿但缓存不生效 | 高 | 入口显式构造真实缓存并传入控制器；验收用 grep 同时锁定构造与传参；本条由本轮复审发现并回填 |
| 无缓存首帧 loading 未置位，页面显示假空态/错误态 | 中 | 水合后同步启动三域加载；新增无缓存首帧用例断言 Skeleton 存在且 Empty/Error 为零 |
| 启动同时发起校验与三路刷新，请求数增加 | 低 | 四路并发与原先「串行校验后三路」相比端到端更短；服务端均为轻量查询 |
| 后台 401 与切换服务器/重新登录竞争，旧结果误伤新会话 | 中 | 会话控制器引入代际号，`restore/login/logout/expire/updateServer` 递增，旧校验结果直接丢弃 |
| 断网冷启动连续三次失败触发多条提示 | 低 | 既有 `_lastError` 去重；同文案只弹一次；测试断言单条 SnackBar |
| 缓存写入抛异常影响加载结果 | 低 | 缓存实现内部吞掉写入异常，保持尽力而为；控制器只在该域成功后调用 |
| Widget 测试中的延时请求/计时器导致不稳定 | 中 | 使用可控延时与 `pump` 推进；断言首帧后及时结束挂起请求 |
| 工作区存在与本轮无关的已暂存技能文件与临时截图 | 高 | 使用路径限定 `git commit -- <本轮路径>`，不提交整个索引；提交前 `git diff --cached --stat -- <路径>`，提交后 `git show --name-only` 复核范围 |
| 本机无 Android 工具链 | 中 | 本轮以格式、分析、Widget/单元测试为本地门禁；APK 冷启动与真机体验由 CI 产物与用户验收 |

## 5. Phase 依赖关系

```
Phase 1 ──→ Phase 2 ──→ Phase 3 ──→ Phase 4
```

Phase 1 提供序列化与缓存契约；Phase 2 消费契约并决定写穿语义；Phase 3 独立于缓存内容，但与 Phase 2 共同决定首帧时序；Phase 4 在前三者稳定后完成装配、回归、文档与提交。

## 6. Subagent 协同规划

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：缓存层与序列化 | 强（模型字段、存储约定、测试替身风格） | 无 | 主线 | 需与既有 `SessionStore`/`PreferencesStore` 模式对齐，隔离会话需重建领域约定 |
| Phase 2：控制器写穿 | 强（加载器代际、筛选语义、清空路径） | 无 | 主线 | 改动集中在单一控制器，拆分会增加合并成本 |
| Phase 3：会话乐观恢复 | 强（启动时序、401 链路、代际守卫） | 无 | 主线 | 涉及启动入口与生命周期，必须与 Phase 4 连续推演 |
| Phase 4：装配、测试与交付 | 中（前三阶段结果已定型） | 低 | 主线 | Widget 冷启动断言依赖真实启动链路；文档与提交必须与测试结果严格一致 |

**协同结论**：本轮不派发 Subagent。改动集中在客户端启动与状态链路，文件数量少但时序耦合强；隔离会话重建上下文的成本高于并行收益，全部由主线执行。

### 核心验收场景

| 场景 | 期望 |
|------|------|
| 有 token + 三域缓存，网络延迟 | 首帧流水在 StreamScreen 子树可见，无 Skeleton/Empty/Error；切换统计/资产/设置时内容已就位；网络返回后无闪烁 |
| 有 token + 缓存，网络断开 | 数据保留，停留 Shell，出现一次连接失败提示，不跳登录 |
| 有 token + 缓存，后台 401 | 清 token、清内存、回登录，业务数据不再渲染 |
| 无 token | 直接登录页，不读取缓存进行渲染 |
| 无缓存 | 首帧为骨架，不出现假空态/错误态；数据返回后正常渲染 |
| 部分域缓存 | 命中域立即渲染，未命中域保持骨架；缺失域不被误判为错误 |
| 三域刷新成功 | 内存更新且下一次冷启动读到的缓存为新值 |
| 筛选态刷新 | 流水缓存不被筛选子集覆盖 |
| 320dp + 2x 字体 | 四个一级页无溢出、无异常（沿用既有用例） |

### 全局备注：

1. 项目定位与设计原则：个人项目、非商业，默认个人设备/个人 VPS 部署使用，避免不需要的冗余设计；遵循简洁、强逻辑的模块化架构和简洁明了的代码设计；优秀、稳固的可扩展架构是第一关键，理性且适当的轻量和轻占用设计是第二关键。
2. 开发环境（Linux x86_64）：本机编译与测试放开；Rust 无环境，不使用；Windows 产物构建与发布验收仍由云端 CI 负责，本机禁止全量构建。本地已装 Flutter、Dart、Go、Git、GitHub CLI（gh）和 Google Chrome(优先连接使用用户提供的已开启远程实例)，可用于静态检查、单元测试、Widget 测试及浏览器运行 Web 版；本地未装且不打算装 JDK、Android SDK、Gradle、NDK；安卓安装包一律由 GitHub CI 构建，本地不构建安卓产物、不连安卓设备运行、不跑集成测试；遇到需要安卓工具链的情况，停下说明，不自行安装依赖；CI 构建的安装包由用户或经明确允许后装到 Windows 上的 x86_64 安卓模拟器或真机，通过 adb 验收。
3. 资源与文件：同一时间只保留必要的进程，开发服务器和浏览器用完就关掉，不启动多个长期运行的服务；测试遵循最小占用（内存/性能/存储），不缓存、不保留任何一次性构建产物；项目文件放在 WSL 自己的文件系统里，不跨到 Windows 盘（/mnt/c、/mnt/d）读写构建相关文件。
4. 版本与安全：沿用项目已经锁定的依赖版本，不顺手升级 SDK 或大版本依赖，确实需要升级时先问用户；不提交签名密钥、证书、令牌或环境变量文件，签名和密钥只放在 CI 的密钥配置里。
5. 浏览器操作：连接用户准备的、已开启 9222 端口的实例。
6. Git 提交规范：Commit 描述使用中文；开头使用标准的英文 Conventional Commits 类型前缀，后方详细描述使用中文。

#### Flutter 开发要求

- 开发阶段主要运行目标是 Web，最终交付目标是 Android，代码必须两边都能编译通过；只在 Web 或只在 Android 能跑都不算完成。
- 引入第三方包前先确认同时支持 Android 和 Web。
- 不要把 Web 专用或安卓专用库直接用在两端都会运行的代码里，避免另一端编译失败。
- 只能在安卓上用的能力（相机、通知、蓝牙、本地文件、后台任务、系统权限等），Web 端要有合理退化处理，并明确告知这部分只能在模拟器上验证。
- Web 端测试通过不等于安卓端没问题；权限声明、原生配置、明文 HTTP 限制、屏幕尺寸和系统版本差异，交付时列为待验证项。
- 每轮 CI 构建加模拟器验收成本高；推送前本地能做的检查要全部做完并通过，不要把 CI 当试错工具。

# Plan：界面去噪重塑、类型标签二级管理增强与移动端深度适配

**状态**：DONE  
**完成日期**：2026-10-02  
**版本**：v1.1（吸收双模型评审意见，修复 SSOT 流转与调序边界）  
**设计哲学**：Microsoft Fluent Design System (Fluent 2)  
**回归测试基线**：全套后端单测与前端 TypeScript 静态编译 100% 通过（`make test` 退出码 0）。

## 1. 背景与目标

当前记账应用已具备核心账单录入、分类统计与基础配置闭环，但在视觉质感、细分配置交互自由度以及小屏移动端体验上存在若干明显短板：
1. 记账流水页卡片使用生硬的单侧彩色硬边框及首字方块图标，视觉过载且破坏 Fluent 2 的温润深度；
2. 新建记账模态窗收支切换隐蔽，用途快捷预置输入属于非必要界面噪声，窗口文案未精简；
3. 消费类型缺少手动调序能力，类型与细分标签仅支持新增和删除，缺乏重命名及二级扩展管理通道；
4. 移动端窄视口下顶栏挤压、底部胶囊筛选与记账悬浮按钮重叠冲突，列表触摸态操作不可见。

本次计划全面落地界面去噪、交互升级与移动端自适应，达成以下目标：
- 净化流水卡片，移除全部首字图标与生硬红绿边框，重构为高阶中性卡片与字体层级；
- 新建记账提供双向胶囊滑块平滑切换收支（默认支出），彻底移除用途说明快捷标签，精简提示文案；
- 消费类型支持手动上下排序，类型与标签均接入二级上下文操作菜单（支持重命名与删除，避免与头部调序按钮冗余）；
- 统计页消除冗余解释文案；
- 移动端视口深度适配：重构底部浮层杜绝按钮重叠（处理 `showFilter=false` 时的退化展示），保障触控友好性与弹窗自适应；
- 维护单一数据源（SSOT）：自顶向下贯通 `App.tsx` 到设置页与各消费视图的实时数据流。

## 2. 阶段划分

### Phase 1：流水页面与账单卡片视觉去噪重构

| 项目 | 内容 |
|------|------|
| **输入** | 既有账目流水页、Fluent 2 卡片阴影与边框令牌 |
| **输出** | 纯净无彩色硬边框、无首字方块图标的账目卡片排版 |
| **验收标准** | 彻底移除卡片左侧彩色边框与首字图标；金额与描述保持严格字阶对比与等宽数字对齐；流水卡片悬浮及触摸操作入口清晰。 |

### Phase 2：记账模态窗交互重塑与文案精简

| 项目 | 内容 |
|------|------|
| **输入** | 既有记账弹窗组件、胶囊滑块设计原型 |
| **输出** | 顶部收支胶囊滑块（默认支出）、文案修正为“记账”、无快捷预置输入标签的纯净表单 |
| **验收标准** | 模态窗顶部具备平滑滑动的收支胶囊切换器；默认激活支出态；用途说明下方无快捷预置标签；弹窗标题由“记一笔账”更新为“记账”；分类标签级联选择面板去除首字图标。 |

### Phase 3：消费类型手动排序与二级操作菜单

| 项目 | 内容 |
|------|------|
| **输入** | 既有基础设置模块、`App.tsx` 全局状态、后端排序与更新接口 |
| **输出** | 支持手动调序与重命名的消费类型与细分标签管理体系、`App.tsx` 联动更新回调 |
| **验收标准** | 消费类型列表移除首字方块图标；提供直接的上移/下移排序控制，采用索引重分配策略规避同值碰撞；类型支持二级菜单进行“重命名”与“删除”（不堆叠重复调序按钮）；细分标签支持二级菜单进行“重命名”与“删除”；`App.tsx` 完整接通更新并刷新配置，全局实时同步。 |

### Phase 4：统计看板微调与移动端全屏深度适配

| 项目 | 内容 |
|------|------|
| **输入** | 统计看板组件、顶栏导航、底部悬浮操作栏 |
| **输出** | 移除冗余说明文案的统计卡片、移动端自适应顶栏与防重叠底部操作系统 |
| **验收标准** | 统计看板彻底删除“点击分类查看细分标签下钻”说明文案；在 320px–390px 移动视口下，底部筛选胶囊与记账圆形按钮无任何重叠遮挡，且在 `showFilter=false` 时正确保持轻量悬浮 FAB；顶栏内容自适应不换行错位；卡片操作按钮在触屏下易于触发；弹窗在移动端以自适应居中或安全区域呈现。 |

### Phase 5：全链路回归验证与构建交付

| 项目 | 内容 |
|------|------|
| **输入** | 前四阶段交付的所有界面与交互代码 |
| **输出** | 静态类型无报错检查、响应式断点类名审查报告、更新后的工程基线 |
| **验收标准** | 执行完整静态检查无报错（`make test` 退出码 0）；代码级断点类名审查通过；原有增删改查业务与统计功能无回归故障。 |

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 视觉设计体系 | Microsoft Fluent 2 | 契合项目既有令牌规范，采用 Segoe UI、微投影与 Acrylic/Mica 空间层级，温润克制 | Material 3 / iOS HIG（违背项目既有约定，混合风格破坏一致性） |
| 收支切换交互 | 物理滑动双段胶囊滑块 | 视觉焦点明确，单手操作面积充足，状态切换具确定性触感 | 原有微型文字药丸（面积过小且隐藏于金额框内） |
| 类型与标签编辑 | 原生弹层二级操作菜单 (Popover) | 仅收纳重命名与删除等低频核心操作，不与卡片头部调序按钮重复 | 平铺展开全部按钮（导致小屏幕严重拥挤爆行）；在 Popover 内部重复放置调序按钮（过度设计） |
| 移动端底部布局 | 协同自适应底部工具条 + `showFilter` 退化判断 | 解决窄屏下居中筛选胶囊与右下角 FAB 按钮物理冲突，并在设置/统计页优雅保持悬浮 FAB 单按钮展示 | 单纯缩小尺寸（在 360px 宽度屏幕依然发生碰撞）；通栏吸底未处理非流水页空白失衡 |
| 排序持久化链路 | 前端序号重排映射 + 两次单实体更新调用 | 针对同值碰撞执行基于数组索引的序号重分配（`idx + 1`），复用现有 `PUT` 接口，无新增后端端点 | 新增重量级批量排序端点（违背 YAGNI，增添非必要后端代码）；直接盲换同值 sort_order（导致 SQL 排序死锁） |
| 状态流转机制 | 顶层 `App.tsx` 驱动 SSOT 同步 | 统一由 `App.tsx` 声明 `handleUpdateCategory` / `handleUpdateTag`，更新后重新拉取 `fetchConfigData()` | 仅在子组件局部修改（导致全局分类/标签状态不同步） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 移动端键盘弹出遮挡记账弹窗输入与提交按钮 | 🟡 中 | 弹窗容器采用弹性自适应高度并设置内部滚动区，提交按钮始终处于可视区 |
| 消费类型与细分标签重命名包含重名导致唯一约束冲突 | 🟡 中 | 提交前前端做基本去重校验，后端 400 冲突由统一 Toast 精准反馈错误信息 |
| 窄屏下底部筛选与 FAB 按钮点击命中区域过小 | 🟢 低 | 设置最小 40px 触控热区并合理分配横向边距，确保触控精准 |
| 触摸设备无鼠标 Hover 导致无法显示操作按钮 | 🟡 中 | 移动端断点下常驻显示半透明操作图标（`opacity-65`），确保功能直接触达 |
| 调序相邻项存在相同 sort_order 导致换序无效 | 🟡 中 | 前端重排时依据数组新排列顺序重新分配序号，确保数值严格递增，彻底消除碰撞 |

## 6. Subagent 协同规划

对照三维效益模型（任务复杂度、上下文关联度、经济与时间效益）评估本阶段委托需求：

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：流水卡片去噪 | 强（紧密关联 Fluent 令牌与卡片布局） | 低（轻量局部差分） | 主线 | 避免跨 Agent 上下文丢失导致视觉风格偏移 |
| Phase 2：记账弹窗重塑 | 强（涉及表单状态、滑块动效与级联） | 低（串行交互递进） | 主线 | 滑块组件与表单模型高度内聚，主线编写更精准 |
| Phase 3：类型与标签管理 | 强（涉及 App.tsx 根数据流与 SettingsPage） | 低（强依赖 API 行为） | 主线 | 菜单状态管理需严密闭环，主线推演高效安全 |
| Phase 4：移动端深度适配 | 强（需统筹全局容器、导航与底部悬浮） | 低（全局协同排版） | 主线 | 需要打通多组件响应式变量，统一调度杜绝冲突 |
| Phase 5：回归验证与构建 | 低（只读验证与测试脚本执行） | 中（可独立执行） | 主线 | 本地编译与轻量测试耗时极低（1.5s），主线直接执行性价比最高 |

> **协同结论**：全阶段任务强依赖当前会话的前端 Fluent 2 视觉上下文与紧密相扣的组件状态。为坚持克制原则并避免上下文割裂，全流程保留主线连贯推进，不作多余派发。

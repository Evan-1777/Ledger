## 1. 背景与目标

2026-10-31 的订阅页交付完成了业务闭环，但页面视觉与交互仍停留在“功能可用”层面。本轮以真实浏览器渲染为基准复核，确认存在分布条不可见、金额/日期断行、暂停视图小计错位、筛选计数错误、无分组标题错位、空分组 0.00/红色标记、FAB 遮挡菜单、表单大面积留白等一批问题。它们不涉及后端契约，属于同一页面的排版、语义与状态一致性缺陷。

**本轮目标**：在不改后端、Web、数据库与依赖版本的前提下，把 Android 订阅页收敛到与流水/统计/资产页一致的成品级表面；同时保证 320dp + 2 倍字体、浅色/深色、空/加载/错误/筛选空态均可用。

### 浏览器复核环境

- Flutter debug web：flutter run -d web-server --web-port=5175 --web-hostname=localhost --no-pub；Chrome 设备模拟 390×844 与 320×800，DPR 2。
- 临时后端：LEDGER_PORT=8081、LEDGER_DB_PATH=/tmp/ledger-audit.db、LEDGER_ADMIN_PASSWORD=audit、LEDGER_CORS_ORIGIN=http://localhost:5175。
- 数据：5 个分组（含 1 个空分组、1 个长名称分组）、9 条订阅（7 使用中、2 已暂停，含长名称与 1/2/5/9/15/20/28/30/31 扣款日）。
- 复核后已关闭页面、停止前后端进程、删除临时数据库与 app/build/web；工作区未留下审计构建产物。

### 2.5 无障碍与细节

- Hero 分布条无 Semantics 标签；Web 端已有“按分组划分的每月固定开支”的等价描述。
- 组菜单/行菜单 tooltip 均为“分组操作/订阅操作”，读屏无法区分具体对象。
- 320dp + 2x 下 Hero 主金额的 FittedBox 把“¥ / 月”一起缩放，金额可能缩到正文以下；需让数字单独收缩，货币与单位保持字号。
- 删除订阅确认文案“删除后不可恢复。Netflix”与分组确认的“「名称」”引号风格不统一。

## 4. 设计决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 页面顺序 | Hero → 页面操作 → 筛选 → 分区列表 | 与资产页“先数据、后操作”一致；首屏先回答“每月多少钱” | 操作置顶（现状，主次颠倒）；把操作塞进 AppBar（图标语义弱，且引入新的全局模式） |
| 页面操作 | 右侧 TextButton.icon「新建分组」+ FilledButton.icon「添加订阅」 | 次级动作降权，主操作保留实心；沿用 SectionHeader 的 TextButton 语言 | 两个大实心/描边胶囊（现状，视觉过重）；仅保留一个入口（分组管理不可达） |
| 页面计数 | 删除筛选下方“共 N 项”独立计数行 | 与 Hero 的“N 项使用中”、组头的分区计数重复；删除即消除 active 筛选计数错误 | 改为按筛选计算（多一处状态与文案，仍有视觉孤岛）；塞进筛选行（320/2x 挤压） |
| 筛选控件 | ChoiceChip(showCheckmark: false) 的 Wrap | 保留可换行能力，去掉选中时的宽度跳动 | SegmentedButton（320+2x 溢出）；FilterChip（同样有勾选位移） |
| 组头 | 统一 16dp 前导槽 + 48dp 尾随槽 + surfaceContainerHigh 底 + 分隔线；标题升为 titleMedium | 未分组与分组三条基线对齐；组头获得分区层级 | 保持现状（未分组错位）；把组头移到卡片外（菜单与分组归属脱节） |
| 组头计数 | 全部“共 N 项”、使用中“N 项使用中”、已暂停“N 项已暂停”；空组不显示计数 | 与可见行一致；空组由“暂无订阅”行承担说明 | 继续用 activeCount（全部视图与行数不符） |
| 组头小计 | 仅当 filter != paused 且 activeCount > 0 显示 active 月合计，否则“—” | 暂停视图不再显示与可见行无关的 active 金额；空/纯暂停组不再显示 0.00 | 暂停视图显示 paused 合计（“/ 月”语义错误）；继续显示 active 小计（现状错位） |
| 组色 | 无使用中项时用 outlineVariant，否则取 finance.chart[index % length] | 空/纯暂停组不再出现支出红；有使用中项的组仍与 Hero 分布条对应 | 换整套调色板（影响资产图表）；去掉色块（标题基线再次错位） |
| 行布局 | 文本 Expanded 吃剩余宽度；金额用 ConstrainedBox(maxWidth: 行宽 * 0.4) + FittedBox；名称 maxLines: 2 | 根除 50/50 平分导致的挤压；金额仍可在极端值收缩 | 继续 Flexible 平分（现状断行）；金额固定宽（2x 溢出） |
| 暂停状态 | 徽标移入元信息“已暂停 · 原扣款日 N 日”；整行 surfaceContainer 底 | 名称获得整行宽度；暂停项整体后退，扫视可跳过 | 保留名称后的胶囊（继续换行）；仅改颜色（对比不足） |
| 元信息日期 | 用 word joiner 阻止“11月15日”内部断行，只允许在“·”处换行 | 解决“11 / 月15日”这类词中断行，不改变可见文案 | 改全局 formatMonthDay（影响流水/统计且测试字符串变化）；截断（丢日期） |
| Hero 分布条 | Row(crossAxisAlignment: stretch) + Semantics(label: '按分组划分的每月固定开支') | 修复零高度根因；读屏获得构成信息 | 给每个 ColoredBox 加 child（临时补丁，仍无高度契约） |
| Hero 金额 | 数字单独 FittedBox，¥ 与“/ 月”保持字号 | 2x 下不再把整行缩到正文以下 | 整行 FittedBox（现状，层级倒挂） |
| FAB | 订阅 Tab 隐藏全局“记一笔”，底部 padding 100 → 32 | “记一笔”与订阅无业务关系，且遮挡右侧菜单；页面自身已有“添加订阅” | 保留（现状遮挡）；换成订阅 FAB（改变全局导航语义，超出本轮） |
| 空态 | LedgerCard 包裹 EmptyState；顶部操作已提供 CTA，空态不再重复按钮 | 与资产页空态一致；避免双入口 | 保留裸 EmptyState（无表面承接）；保留双 CTA（重复） |
| 确认框 | 共享 ConfirmDialog 的确认按钮使用 scheme.error/onError | 破坏性动作与普通主操作区分；全站一致 | 仅订阅页自绘确认框（重复实现） |
| 表单高度 | 内容自适应，最大 86% 可用高度；Column(mainAxisSize.min) + Flexible 滚动区 | 消除固定高度留白；键盘弹出时仍可滚动 | 继续固定 86%（现状空洞）；固定 60%（大字体字段放不下） |
| 表单校验 | 字段级 errorText + 首个错误 FocusNode；API 错误保留顶部条 | 错误出现在对应字段旁，键盘遮挡也不丢失 | 仅顶部条（现状，可能看不到） |
| 表单关闭 | 保留 isDismissible:false/enableDrag:false，X/返回退出 | 避免提交中被下滑关闭导致“已保存但无反馈”；与上一轮约定一致 | 空闲可下滑（需处理提交中路由级关闭，收益不抵复杂度） |

## 5. 阶段划分

### Phase 1：派生语义与文案（TASK-001 ~ TASK-002）

- **输入**：SubscriptionSection 现有字段、筛选枚举、日期格式化。
- **输出**：按筛选切换的组头计数/小计规则；暂停/空组文案；续费日期不可断行格式；对应纯函数/Widget 用例。
- **验收**：任何视图下组头数字与可见行一致；暂停视图不再出现 active 小计；日期不出现“11 / 月15日”式断行。

### Phase 2：页面结构与 Hero（TASK-003 ~ TASK-005）

- **输入**：Phase 1 的文案/语义、LedgerCard/EmptyState 共享构件、Shell 导航索引。
- **输出**：Hero 分布条可见且有语义；页面操作移到 Hero 之下；删除独立计数行；筛选胶囊无勾选位移；空态卡片化；订阅 Tab 隐藏 FAB、底部 padding 收紧。
- **验收**：首屏先 Hero 后操作；390/320 浅色/深色无溢出；FAB 不再遮挡菜单；空态只有一个主 CTA。

### Phase 3：分区与行排版（TASK-006 ~ TASK-007）

- **输入**：Phase 1 的计数/小计规则与元信息格式。
- **输出**：组头前导/尾随槽对齐、表面分层、标题字阶；行文本列吃剩余宽度、名称两行上限、金额有界收缩、暂停状态移入元信息、暂停行底色、菜单具名 tooltip。
- **验收**：未分组与分组标题/计数/金额右缘对齐；390dp 常规行元信息不词中断行；320dp + 2x 无横向溢出、行高有界。

### Phase 4：表单与确认（TASK-008 ~ TASK-010）

- **输入**：SubscriptionSheet、GroupSheet、共享 ConfirmDialog。
- **输出**：表单内容自适应高度；字段级校验与焦点；新建/编辑按钮文案；删除分组 0 项文案；确认框危险色；创建后筛选回到可见状态。
- **验收**：390dp 表单高度 < 屏高 70%；错误在字段下方可见；删除按钮为错误色；暂停筛选下新增订阅后自动回到“全部”并能看到新行。

### Phase 5：测试、文档、归档与提交（TASK-011 ~ TASK-013）

- **输入**：全部实现与测试。
- **输出**：订阅页/Shell/共享构件用例；格式、静态检查、全量测试、Web 构建门禁；Project.md 同步；归档与白名单提交。
- **验收**：门禁退出码 0 并记录项数；320dp + 2x 通过；Project.md 只写已落地事实；归档目录同时含 Plan.md 与 Tasks.md；提交不夹带既有暂存技能文件、temp 截图与构建产物。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 行布局改为“文本 Expanded + 金额有界”后，超长金额在 320dp + 2x 下被 FittedBox 缩得过小 | 中 | 金额上限取行宽 40%，数字保留 tabular figures；320dp 用例断言金额右缘不出界且字号不小于 labelSmall |
| 组头前导/尾随槽改变后，长组名与金额在 2x 下互相挤压 | 中 | 名称 Expanded + ellipsis，金额有界 + FittedBox；320dp + 2x 断言组头高度不超两行 |
| 删除独立计数行后，测试与用户熟悉的“共 N 项”消失 | 低 | 组头与 Hero 已提供计数；Project.md 记录该取舍；如用户要求可加回筛选行右侧并做按筛选计算 |
| 隐藏订阅 Tab 的 FAB 影响“随手记一笔”路径 | 中 | 仅订阅 Tab 隐藏，其余四页保留；Shell 用例覆盖；如需全局调整另开阶段 |
| 表单内容自适应后键盘弹出高度不足 | 中 | ConstrainedBox(maxHeight: 可用高度 * 0.86) + 滚动区 + 底部 SafeArea；320dp + 键盘用例 |
| 共享 ConfirmDialog 改色影响流水/设置删除确认 | 低 | 全站统一危险色是预期改进；跑既有确认框用例与全量回归 |
| 暂停筛选下新增后自动切回“全部”改变用户筛选状态 | 低 | 只在“新增成功且当前筛选非全部”时切换；取消不切换；用例覆盖 |
| 归档/提交夹带工作区既有暂存文件 | 高 | 提交使用 git commit --only -- 白名单；归档后只 add 归档目录；提交前后核对 git status/git show --stat |
